# Rendering and the document store

Scope: the PDF engine (pdf-lib, determinism, fonts, symbol fonts), the preview route and anchors, money formatting on paper, and the document store (`files.*`: bytes, versions, links, brand assets). What documents say is `document-content-and-issuers.md`.

## Rendering a document: why the engine is pdf-lib (T3.8)

- **A rendered document's content hash is evidence** (`crm.engagement_letter.signed_content_hash` vs `files.document_version.content_hash`: "is the file the client holds the one we issued"). So the renderer is a **pure function of its input**: re-rendering unchanged data reproduces the bytes exactly.
- That chose pdf-lib (pure JS, no native modules, draws exactly what it is told). A headless browser cannot promise byte-stability across versions (font hinting, image encoders, PDF writer move between Chromium releases; a base-image upgrade would silently stop every re-render matching). **Cost: layout is hand-built**: no CSS, no automatic table; `infrastructure/render/pdf-renderer.ts` carries a small column-and-flow engine behind `DocumentRenderer`. Reversible, but a replacement answers determinism first.
- **pdf-lib writes CreationDate, ModDate and Producer from the clock and its own version.** All three are pinned from the document's own issue date; without that, a render-twice test passes inside one millisecond and fails in production.
- **Three collaborators, none learns another's job:** `RenderableDocument` (`domain/render`) is a neutral description (no fonts, margins, page size); `RenderSource` (Postgres) knows what a letter contains; `DocumentRenderer` knows what a page looks like. A renderer holding repositories would duplicate read logic that drifts.
- **Money on paper: one formatter (audit 2026-10-03, B19 / CA#49).** `documentMoney` (`domain/render/money.ts`) for documents drawn since 0334: "₹12,50,000" (lakhs) for rupees, "AED 5,000" with its code for every other currency, paise only when present, always two places on a tax invoice ("₹5,900.00"). Digits regrouped by hand, never `Intl` and never a JS number (bytes must not depend on the machine's ICU). Letters/invoices issued BEFORE 0334 keep "INR 1,250,000.00", recognised by no `printed_parties`; `layout.test.ts` still pins them. The ISO code is a product decision (cross-border: a bare symbol is ambiguous in Dubai or Delaware). **Open: PDF INR grouping** (W4D).

### Fonts are a CHAIN (T3.9)

- No single Noto Sans file covers it (measured): `latin` has the em dash, not the rupee sign; `latin-ext` has the rupee sign, not the basic range; `devanagari` has both plus Devanagari. Text is segmented into runs, each drawn with the first font that can draw it; adjacent characters on one font merge. Noto Sans is **OFL-1.1**, an npm dependency (versioned, auditable); `subset: true` embeds only used glyphs.
- **Two symbol fonts, embedded ON DEMAND (2026-09-29):** Noto Sans Math (`≤ ≥ ≠ ≈`, arrows, `✓`, box/geometric) and Noto Sans Symbols 2 (`✔ ✗ ☐ ⚠`), OFL-1.1, one weight each. Found on QA: the standard service template writes "≤1,000 entries" and every proposal quoting it was refused. Not embedded like the first three (that adds two fonts to every letter and moves pinned hashes). The guard returns every character it walked; `FontSet.prepare` embeds only the symbol fonts needed (chain order, deterministic); a document with no symbol is byte-for-byte unchanged (all 40 PDFs in `layout.test.ts`). `U+FE0E`/`U+FE0F` (emoji style selectors after `⚠`) are left out, not refused.
- **`font-set.ts` imports `regenerator-runtime`** (shim for an upstream defect in `@pdf-lib/fontkit` that throws on complex shaping tables, i.e. only Devanagari). Do not remove it; **do not upgrade to fontkit 2.x** (it changed the subset API pdf-lib calls).
- **Second upstream defect, in the SUBSETTER: draws nothing instead of throwing.** A subset under 64 KB uses short `loca` (offsets halved) and glyphs are not padded to even length, so every glyph after an odd-length one starts a byte early; FreeType (Chrome, MuPDF) draws empty space. Noto Sans has no odd-length glyph; Math and Symbols 2 have over a thousand each, and ≠ → ✔ ✗ ☐ ⚠ came out blank with every test green. `evenGlyphFontkit` in `font-set.ts` pads each odd glyph with one zero byte, on this module's subsets only. `layout.test.ts`'s `brokenGlyphs` holds every embedded glyph to its source (same outline, not a byte shorter; an outline check alone passes a blank glyph). **When a font joins the chain, rasterize and LOOK at a rendered page, not only the tests.**
- **The guard is derived from the fonts, never a hardcoded range.** It REFUSES rather than mangles: `UnrenderableText` names the character, code point, field and what the chain carries (dropping a letter from a client's name on a legal document is worse than nothing). Remaining gaps: colour emoji (`✅ ❌`), CJK, Arabic.

## The preview IS the PDF (2026-09-28)

Screens used to draw an HTML imitation of each document; two layouts drift. Now there is ONE layout, the renderer's, and the screens draw the server's PDF page by page (pdf.js on canvas, frontend).

- **`POST /api/v1/documents/preview`** takes `render`'s body (`kind`, `subjectRef`) plus optional `asOf`; answers JSON: bytes (base64), `contentHash`, `pageCount`, `anchors`, `datedAsIfSent`, issuing company, `missingBrand`. It **files nothing** (no blob, document, link, event: `FileStoreService.preview`; service and integration tests count all four). Permission `party:write` (same rows, same fees as `render`).
- **It does not break "bytes leave by ONE route" (T3.6)**: that rule is about STORED bytes; the preview stores nothing, returns no storage key, and draws rows the caller can already read under RLS through the same renderer.
- **A draft is drawn as Send will leave it.** `RenderSource.describe` takes `asIfSentOn`; for a DRAFT it fills in exactly what Send stamps: a proposal's date (the firm's day); a letter's `issued_on` when blank (`coalesce`, as `markSent`) and the firm's block from the standing signatory plus the issuer's signature in force (what `send` pins, 0081). The renderer is deterministic, so an unedited draft previews the bytes Send produces the same day; `tests/render/preview.integration.test.ts` proves it by hash (proposal preview = its pinned PDF of record; letter = envelope's PDF). A document already out is drawn as it stands. A letter's `asOf` is held to the firm's day ±1 (`PreviewNotCallersToday` → 400 `NOT_CALLERS_TODAY`); a proposal ignores it.
- **Anchors: where each editable piece was drawn, never drawn themselves.** Flow pieces, table rows (`rowAnchors`) and covers carry an optional `anchor` (`Anchor`, `domain/render/model.ts`): `proposal.title|background|validUntil|preparedFor|preparedBy`; `letter.issuedOn|addressedTo|subject|background`; `line:<id>.name|scope|volumeLimits|clientObligations|exclusions` (a multi-company item is keyed by its first line); `fee:line:<id>`, `fee:group:<id>`; `section:<groupId>.title|intro|deliverables|clientObligations`; `block:<id>`; `add:<kind>` on a Notes heading. `PdfLibRenderer.renderWithAnchors` reports one rectangle per occurrence per page (PDF points from top-left) as a SIDE OUTPUT of the same pass (`Face.draw` measures into an `AnchorTracker`, changes nothing drawn); the running head and a repeated table header are drawn `quiet`. `tests/render/anchors.test.ts` hashes render with/without collecting and with/without anchor keys: equal; `layout.test.ts` untouched.

## The document store: bytes and the one route they leave by (T3.6)

`files.document` / `document_version` / `document_link` / `brand_asset` (0037). A separate schema on purpose: `crm.document_block` (G1.7) is PROSE inside a proposal and `crm.document_ref_series` (0020) hands out `PR-2026-0007`; a `crm.document` would read as "the document a block belongs to". `domain/document` = words; `domain/filestore` = bytes; they meet where a rendered letter becomes a file.

- **Bytes leave by ONE route; there is no pre-signed URL** (design position): a pre-signed URL outlives the session and is checked by a vendor, so it answers to none of the four gates. The version row naming the storage key is read under RLS, so the key is unreachable before it could be used. The port has no method that returns a URL; adding one is the thing not to do. Stored files leave only through `fetchBytes`.
- **`document_version` is append-only by GRANT** (`bib_app`: SELECT + INSERT only, like `ledger`); `document_link` has no UPDATE either. **Detaching is WITHDRAWING (0302, decided 2026-09-25):** the firm answered an attachment made in error should "remain visible". `withdrawn_at`/`withdrawn_by` are the ONLY two columns `bib_app` may UPDATE; a trigger freezes a withdrawn row; the unique key is a partial index over LIVE links so the document can go back on; verb `document.link_withdrawn`. `listForSubject` hides withdrawn links, `linksOf` shows them marked.
- **Storage is content-addressed** (key from sha256): a re-sent file stores one blob, and **two documents can share a blob**, so `BlobStore` has no `delete` and must not grow one. Retention/erasure is a deliberate feature with reference counting behind it.
- **`subject_ref` carries no FK and cannot** (points at a table by `subject_kind`, following `delivery.job`'s `(source_kind, source_ref)`). The `subject_kind` CHECK is the containment. A new kind is a migration AND a case in `linksOf`'s label resolution.
- **Brand assets are keyed on the ENTITY, never the firm** (a firm on two letterheads must not print the Indian logo on a US-issued letter). Superseding = insert + cleared flag under a partial unique index (`WHERE is_active`); the mark in force at issue stays resolvable. Kinds include `proposal_cover` (`document-content-and-issuers.md`).
- **The filesystem blob store is the FOURTH honest-registry stub**: `validateServer` refuses a production-like boot on it (replicas do not share a disk: an upload through one pod is a 500 through the others; a container filesystem does not survive a restart, leaving metadata that outlives its bytes).
- A `DocumentRenderer` port was written and deleted before T3.8 under the rule that a contract designed against no consumer ends up wrong (the reason T2.5 deferred `workflow_template`).
