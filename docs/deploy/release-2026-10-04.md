## Before deploying (Terraform / Cloud Run)

1. **Worker SMTP.** Apply `infra/terraform/run_worker.tf` and `iam.tf` from this branch. The worker
   sends the weekly advance summary and the notification emails, so it needs `BIB_SMTP_PORT`,
   `BIB_SMTP_USER`, `BIB_SMTP_SECURE` and the `smtp-password` secret. It also needs
   `BIB_APP_BASE_URL` set to the real web URL, because the links in the emails use it.
2. **Owner pool removed.** `BIB_DB_POOL_OWNER` is no longer read. Only `cmd/migrate.ts` uses the
   owner credential.
3. **`BIB_MAIL_FROM_NAME`** should be the product name. The firm's name is now in the mail itself.
4. **Deploy order.** Backend first, so migrations run and the worker is redeployed; then the
   frontend. The frontend calls routes the old API does not have.
5. **Worker queues:**
   - `billing.dues`: daily.
   - `billing.advance-digest`, `notify.advance-reminders`, `notify.email-digest`: hourly
     (`BIB_WORKER_ADVANCE_DIGEST_CRON`).
   - `notify.fanout`: every minute (`BIB_WORKER_NOTIFY_CRON`, optional).
   - `notify.prune`: daily.

## What users see the day it is deployed

The "Automatic billing" switch stays **OFF** for every firm. Some things change anyway:
- **Draft numbers.** A new invoice draft has no number until an admin issues it. Old pre-0322
  numbered drafts are refused at issue if out of order: cancel and raise again (B51).
- **Signing.** A signed letter starts its work at once and drafts its advance invoice. Each
  company needs a default tax rate (Your firm → Automatic billing), or the advance waits under
  To raise.
- **Letters waiting for an advance today** start on the next daily run. Where an advance was
  already invoiced by hand, the admin Links it instead.
- **Notifications.** The bell appears, and a daily 09:00 email digest goes out (each person can
  switch email off).
- **Audit behaviour changes.** Fees are hidden from logins without fee visibility (403
  `FEES_NOT_VISIBLE`), invoice rounding, a paid invoice cannot be cancelled, and more. See the
  audit note.

**Before anyone switches Automatic billing ON on QA,** run
`scripts/billing-preflight.sql` (in this repo). It is read-only and finds:
- letters with quantity ≠ 1 on a recurring line, which would bill N× per period;
- old numbered drafts;
- invoices whose total changes under 0325.
