## What is in it, in plain words

1. **Each company keeps its own financial year and time zone** (Q036). An India company on
   April-March and Delhi time, a US company on its own year and Los Angeles time. Invoices, invoice
   numbers, billing periods, letters and proposals are dated on the issuing company's calendar.
   Reminders to people (To raise ageing, Overdue, dunning, the digest) stay on the firm's day.
   - Set on **Your firm → Companies**, "Year and clock".
   - Empty means "same as the firm".
2. **A bill in arrears is made on the period's last day** (Q042). October's bill is dated 31 Oct, not
   1 Nov.
3. **Work vs Billing** (Q041). A new tab under **Invoices**, and a link on each client's page. It
   shows, for each client, service and month: the job, the bill, the invoice and the payment.
   Flags say "job done but no bill", "billed but unpaid", and so on. Download as CSV.
4. **Several signatories** (Q005). The firm keeps a list of partners who can sign, each with their
   own signature image. Each draft letter picks one ("Signed by"). The default is unchanged.
5. **Several currencies on one proposal or letter** (Q006, Q008-Q011). For example, ₹15,000 per
   month + AED 4,000 per month.
   - Totals are one figure per currency, never added together.
   - Each currency bills on its own invoice.
6. **Daily exchange rates** (Q009). Rate boxes are pre-filled with the day's rate from a free feed,
   and can still be typed over. The dashboard has a new "Recurring fees by currency" card.

On top of the merges, the backend has three commits of its own:
- **d3d611a, Work vs Billing cuts periods on the company's year, as the sweep does.**
  - The problem: the billing sweep cuts a service's periods on the year pinned on its engagement,
    else its company's year, else the firm's. Work vs Billing still asked only the firm's.
  - The effect: for a company on its own year, a quarterly service would show an expected bill
    for a quarter the sweep never bills.
  - The fix: Work vs Billing now makes the same choice. There are two unit tests, and both fail
    without the fix. 10x is unaffected today, because every 10x company is April-March.
- **81fe51b, the smoke script reads a proposal's `totals` as an array.** Multi-currency changed the
  API shape, and the script had not caught up. The result was 4 false failures; the product was
  fine.
- A docs commit with this note in `docs/deploy/`.

## Env vars and config

Only the FX feed is new. Each setting has a safe default, so **nothing must be set**:

| Variable | Default | What |
|---|---|---|
| `BIB_FX_FEED` | `live` | `off` = no network; rates are typed only, as before |
| `BIB_FX_EXCHANGERATE_API_KEY` | unset | Optional. Free key from exchangerate-api.com. Without it, the CC0 Currency API serves alone. If you set it, map a Secret Manager secret into `run_api.tf` **and** `run_worker.tf`, like `BIB_SMTP_PASSWORD` |
| `BIB_FX_TIMEOUT_MS` | `10000` | Feed timeout |
| `BIB_WORKER_FX_CRON` | `30 1 * * *` | Worker queue `platform.fx-refresh`, daily at 01:30 UTC (07:00 IST) |

- The API and the worker need outbound HTTPS to `v6.exchangerate-api.com`, `cdn.jsdelivr.net` and
  `*.currency-api.pages.dev`. Cloud Run allows this by default.
- `worker:once` does not run the FX refresh. Rates still arrive, because the API fetches a missing
  day the first time someone asks for it.
- No new permissions to grant, and no Terraform change is required.
- Still open from 10-04, if not done yet: the worker's SMTP vars and `BIB_APP_BASE_URL`.
